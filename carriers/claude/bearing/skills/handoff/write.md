# handoff — 書く

⚠ **「なぜ」と「置き場」は傍らの `SKILL.md` が持つ。** ここは `w` で呼ばれたときの手順だけを持つ。

**何を残し何を省くかの judgment があなたの仕事の全てであり**、それを機械に渡してはならない —— それが native な圧縮に欠けているものだからだ。⚠ **人間に見せて確認を得てから land すること。**

land だけは機械である（旧 baton の archive 退避 → `composed-at` の刻印 → 配置）:

```bash
bearing-handoff.mjs write < <あなたが著した baton>
```

⚠ `read-at` は書かない —— 新しい baton は「まだ読まれていない」が正で、この経路は書かれていても除去する。

🔴 **`transcript:` は*あなたが*書く —— 機械は解いて確かめるだけである**（導き方は末尾の `### 自分の transcript`）。🔴 **これは「要約が原理的に運べないもの」の取り出し口である** —— **前の対話の逐語・error の原文・生成した code。** 🔴 **native な圧縮がこの形を採っている**（実測 2026-09-11、対象: 本 repo の圧縮要約）—— **要約は transcript を*貼らず*、絶対 path 1 本と「何を取りに行く欄か」の 1 行だけを置いていた**（6,431,899 字に対し要約は 18,033 字 ＝ 0.28%）。

⚠ **`composed-at` と同じ側の欄ではない。** 時計は機械が持っているが、🔴 **「この対話は誰か」を知っているのはあなただけである。** ∴ **名乗らなければ欄は置かれない** —— **機械が代わりに埋めることはしない。** ⚠ **解決しない path は刻まれない**（欄そのものが置かれない）—— **開けない path は、欄が無いことより悪い。**

## 手順

1. 既存の baton があれば archive へ退避する（`archive/<UTC>.md`、`YYYY-MM-DDTHHMMSSZ.md`）。
2. 下記の形で baton を書く。
3. **何を残し何を省いたか**を 1〜2 行で人間に報告する。

### 原則

- **再導出できるものは省く。** code の実体は git から、目的の木は `docs/aims/` から後任が読める。書くのは*そこに無いもの*だけ —— 今どこに立っていて、何を試して捨てて、次に何を拾うか。
- **forward に選ぶ。** 網羅ではなく、後任が次の一手を打つために要るものを選ぶ。
- **迷ったら短く。** 長い baton は authoring を怠けた証拠であることが多い。
- 🔴 **数を書いたら、その数を出し直すコマンドを*同じ場所に*置く。** ⚠ **参照は運べても、参照が支えている主張は運べない** —— **数は世代を跨ぐたびに安く写せるのに、それが何の在庫なのかは誰も再検算しない。** ∴ `open-todo: 4` と書くなら、**その 4 を出す手をその隣に書く**（別の節へ寄せてはならない —— **離れた瞬間、数だけが写る**）。⚠ **出し直す手が無い数は、baton ではなく corpus に属する。** 🔴 **2026-09-10 に踏んだ**: 裸で受け取られた `open-todo: 1` が、**その todo が住む node を取り違えさせた。**
- 🔴 **他人の系についての主張を運ぶなら、階級と射程を一緒に運ぶ。運べないなら運ばず、corpus を指す。** ⚠ **上と同じ形である** —— **「出し直す手が無い数は corpus に属する」なら、こちらは「階級を運べない主張は corpus に属する」。** 🔴 **2026-09-11 に測った**（対象: 本 repo の baton と native な圧縮要約）: **native な圧縮は主張を運びながら日付・対象・射程の限定を落とす** —— 「commit sha は host の merge 慣習が書き換える（実測 2026-09-10、対象: `#53`）。**配り先の慣習は知りえない**」が「every PR lands as one commit ∴ force-push is avoidable」になった。⚠ **baton も同じ形を持っていた**: 「`.jsonl` の `isCompactSummary` 行に全文が在り、読める」は**日付も対象も持たない現在形**である。🔴 **落ち方は 2 通りで、危険なのは片方だけ** —— **丸ごと落ちれば不在として現れる（安い）。剥がれて運ばれれば確信として現れる（高い）。**

### 形

```markdown
---
composed-at: <ISO8601 UTC>
transcript: <自分の session の id。⚠ **下の「自分の transcript」で確かめたものだけ**>
task: <今取り組んでいることの 1 文>
---

## ▶ Task
<何をしようとしているか。1〜3 行>

## Settled
<この session で確定したこと。後任が蒸し返さなくてよいもの>

## Open & next
<未決のまま残すもの。次に拾うべき一手を先頭に>

## Tried & set aside
<試して捨てた手段と、その理由。同じ轍を踏ませない>

## 逐語
<人間自身の言葉。⚠ 言い換えてはならない —— 言い換えた瞬間、それは私の要約になる>

## Pointers
<読むべき aim slug / file:line / PR 番号。内容ではなく在り処だけ。⚠ 数の再検算はここへ寄せず、数の隣に置く>
```

セクションは空なら省いてよい。**`Tried & set aside` は特に価値が高い** —— これだけは後任が git からも aim からも再導出できない。

⚠ **`## 逐語` は native な圧縮が持っていて baton が持っていなかった欄である**（実測 2026-09-11、対象: 本 repo の圧縮要約 —— **人間の逐語 22 件が独立した節で保たれていた**）∴ **取り入れた。** 🔴 **`Tried & set aside` と同じ理由で価値が高い** —— **選んだ逐語は、後任が git からも aim からも再導出できない**（transcript は在っても、どれが効いた 1 文かは在らない）。

⚠ **`read-at:` は書かない。** 読む側が刻む欄で、新しい baton は「まだ読まれていない」が正。退避された旧 baton は自分の `read-at` を持ったまま archive に残る。

### 自分の transcript

**値は自分の session の id 1 つでよい**（`transcript: bfaddb5e-b2c5-…`）—— ⚠ **dir は機械が導き、実在を確かめる。** 絶対 path で書いてもよい。相対 path は拒まれる（baton は別の cwd で読まれる）。

🔴 **`~/.bearing/units/<unit>/session` を見て写してはならない。** ⚠ **あれが答えるのは「最後に prompt を送った対話」であって「あなた」ではない** —— 同じ unit で 2 つの対話が並走すれば取り合う。🔴 **並走はこの機体で既に起きていた**（実測 2026-09-12、対象: `~/.claude/projects/` の当該 unit の dir —— **transcript 32 本のうち、時間帯が重なる対が 3 組。相手は同じ cwd で打たれた短命な session である**）。⚠ **`~/.claude/projects/` を mtime で漁ることも同じく禁じる** —— **最も新しい file が、あなたのものだとは限らない。**

**自分で導き、確かめる:**

- **env が持っていることがある** —— scratchpad の path に session の id が入っている（実測 2026-09-12、対象: この harness の system prompt。⚠ **他人の系である ∴ 黙って変わりうる**）。
- ✅ **陽性対照はこれで取る** —— **直前の人間の発話で grep すれば、自分の transcript に絞れる:**

  ```bash
  grep -lF '<人間が直前に言ったことの一節>' ~/.claude/projects/*/*.jsonl
  ```

  ⚠ **自分の発話では測らない** —— **まだ file に落ちているとは限らない。** 🔴 **人間の発話は submit の時点で落ちている**（実測 2026-09-12、対象: この unit の transcript 32 本 —— **1 本に絞れ、env 由来の id と一致した**）。⚠ **この glob は harness の置き方に依っている** ∴ 0 本なら glob を疑う（`find ~/.claude/projects -name '*.jsonl'`）。
- 🔴 **1 本に絞れなければ、書かない。** **欄が無いことは安い** —— 読む側は「無い」と知るだけである。**他人の path を指すことだけが高い** —— 読む側は**別の対話の原文を、前の対話の原文として読む。**
