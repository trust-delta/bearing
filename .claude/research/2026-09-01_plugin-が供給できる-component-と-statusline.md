# plugin が供給できる component と、statusline がその外にあること

調査日: 2026-09-01
出典: https://code.claude.com/docs/en/plugins-reference
併せて実測: `claude plugin details bearing` / `~/.claude/settings.json` / `~/.claude/statusline.sh`

## 問い

statusline は plugin の管轄範囲か。

## 答え —— 供給できない

plugin が供給できる component（docs の列挙）:

Skills / Commands / Agents / Workflows / Hooks / MCP Servers / LSP Servers /
Output Styles / Themes（experimental）/ Monitors（experimental）/ Channels / **Executables（`bin/` が PATH に入る）**

`claude plugin details bearing` の inventory も Skills・Agents・Hooks・MCP・LSP の 5 種しか数えない。
**statusLine はどこにも無い。**

plugin root の `settings.json` については docs が明示的に制限している:

> "**Settings:** `settings.json` — Default configuration applied when the plugin is enabled.
> **Only the `agent` and `subagentStatusLine` keys are supported**"

⚠ `subagentStatusLine` は **subagent（agent teams）用**であって、セッション本体の statusLine ではない。

∴ **statusLine は user / project の `settings.json` の `statusLine` key（`{type: "command", command: ...}`）
にしか置けず、plugin が宣言して載せることはできない。**

## ただし「供給」と「装着」は分けられる

plugin の **`bin/` は PATH に入る**（Executables）∴ **statusline を描く実行ファイルを plugin が配ることはできる。**
人間が `settings.json` の `statusLine.command` にその名を 1 行書けば繋がる。

**供給は plugin、装着は人間の 1 行** —— この分割は、bearing が他所でも採っている
「道具は可能にするところまで、宣言は人間」と同じ形になる。

## ⚠ 併せて見つかった事実: statusline に前身の経路がもう 1 本生きている

`~/.claude/settings.json` の `statusLine.command` は `~/.claude/statusline.sh` を指し、その中身は:

```
# tmai statusline hook — forwards statusline JSON to tmai, then delegates display
# Generated by `tmai init`. Re-run `tmai init` to regenerate.
```

- statusline の JSON を **`http://localhost:9876/hooks/statusline`（tmai daemon）へ POST**（fire-and-forget, `-m 1`）
- 表示は **`npx ccstatusline@latest`** に委譲

∴ `~/.claude/skills/aim` の symlink を外した後も、**前身へ向かう経路が statusline に 1 本残っている。**
⚠ これも untracked なローカル設定ゆえ `bearing-trace` には原理的に映らない。
⚠ **tmai MCP server はまだ接続されている ∴ この daemon が生きていること自体は前身の残骸とは限らない。**
外すかどうかは人間の判断。
