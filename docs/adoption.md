# 採用する前に —— 何を要求され、何があなたの act として残るか

このページは **bearing を採るかどうかを決めるためのもの**である。使い方の手順は
[`README.md`](../README.md) に在る。ここが述べるのは**契約** —— **採ると何がリポジトリに置かれ、
その後どの act があなた自身に残り続けるか。**

## bearing は何を目指しているか

コーディングハーネスが持っていないのは、**セッションより長く生きる問い**への持続的な答えである
—— 「これは何のためか」「我々は何をなぜ決めたのか」「code はそれが書かれた理由から離れていないか」。
bearing はそこへ 3 つの機構を接ぎ木する: **aim**（目的と手段の木）・**handoff**（圧縮の前に著される
baton）・**drift**（ズレの機械的な可視化）。⚠ **ハーネスを置き換えず、走る場も足さない。**
それぞれが何をするかの表は [`README.md`](../README.md) の「3 つの機構」に在る。

🔴 **そして、その全部が 1 つの非対称の上に立っている** —— **目的を pin することと、目的が達成された
と宣言することは、人間の act である。** エージェントは木を保守し、手段を提案し、実装する。
**だが「何のためか」と「それが満たされたか」は渡さない。** ⚠ **これは設定ではなく、機構の形そのもの
である** —— 以下の要求も、残る act も、すべてここから出ている。

## 採ると、何が置かれるか

⚠ **リポジトリに残るのは 3 つだけである。** 残りはすべてあなたの home の下に置かれ、
リポジトリには 1 バイトも書かれない。

| 打つもの | 置かれる先 | 何が |
| --- | --- | --- |
| `claude plugin install` | `~/.claude/plugins/` | plugin の実体。⚠ **リポジトリには何も残らない** |
| `/bearing:setup-aim` | **リポジトリの `CLAUDE.md` 末尾** | 法の block（エージェントへの不変の指示）。marker は HTML コメント ∴ **context を 1 token も食わない** |
| 〃 | **リポジトリの `.claude/skills/aim/`** | aim skill 一式。⚠ **置いた瞬間からそのリポジトリのもの** —— track するか・直すか・古いままにするかは、あなたが決める |
| （あなたが書く） | **リポジトリの `docs/aims/`** | aim node 本体。`--dir` で別の場所を宣言できる |
| `/bearing:setup-statusline` | `~/.claude/` ＋ user settings の 1 行 | statusline の面。⚠ **project には何も書かない** |
| `/bearing:setup-surface` | `~/.claude/bearing-aim.html` | 木を browser で見る 1 枚 |
| `/bearing:handoff-w` | `~/.bearing/units/<unit>/` | baton。⚠ **リポジトリの外**（`BEARING_HOME` で移せる） |

⚠ **aim を採らないリポジトリには、hook は 1 バイトも出さない。** 法の block が無ければ黙る ——
**corpus が在っても黙る。** 「使っている」ことは「この機構を通したい」という宣言ではないからである。
（例外は未読の baton 1 つ。handoff は aim に依存しない。）

⚠ **外し方も置き方と同じだけ用意されている** —— `/bearing:setup-aim --remove` は block を外す
（skill は残る。置いた後はあなたのものだからである）。`/bearing:setup-statusline --uninstall` は
1 行を外す。**書いた corpus はあなたのリポジトリに残る** —— それは plugin の持ち物ではない。

## その後、何があなたの act として残るか

⚠ **これは「やってもよいこと」の一覧ではない。** 🔴 **どれもエージェントが**代わりにできない**もので
あり、あなたがやらなければ**誰もやらない**。**機構はこれらを催促はするが、肩代わりはしない。**

1. **`aim:` を pin する** —— 目的 1 文。⚠ **エージェントはこれを書き換えない。** 動かすべきだと
   考えたら候補を出してくるが、**確定はあなたの act である。**
2. **`parent:` を決める** —— その目的が木のどこに座るか。
3. **`state:` を宣言する** —— `open` / `done` / `dead`。🔴 **エージェントが `[todo]` を尽くしても、
   それは「実装された」であって「目的が満たされた」ではない。** ⚠ **満たされたかを述べられるのは
   あなただけである。**
4. **`# ESCALATION` に答える** —— そこに書かれるのは「Go だけでは進めない」点だけである。
   ⚠ **あなたが答えるまで、その node は誰の手でも進まない。**
5. **`# OBSERVATION` の票を見る** —— エージェントが「何を見れば満たされたと言えるか」を書く。
   ⚠ **見るのはあなたである。**
6. **handoff を打つ** —— `/bearing:handoff-w`（著す）と `/bearing:handoff-r`（読む）。
   ⚠ **モデルからは起動できない**（baton の退避は取り消せないため）∴ **打つのは常にあなたである。**
7. **版を上げる** —— `claude plugin update` と、置いたものを揃え直す `/bearing:setup-aim --update`。
   ⚠ **忘れても何も言わない面が在る** ∴ 更新は明示の act である。

## 何を要求されないか

- **書き方の作法を全部覚えること** —— 要らない。⚠ **body を書くのはエージェントである。**
  あなたが触るのは frontmatter の 3 行（`aim:` / `parent:` / `state:`）だけで足りる。
- **最初から木を設計すること** —— 要らない。⚠ **node は目的 1 文と親だけで生まれてよく、body は
  後から積まれる。** 木は**検証から後ろ向きに育つ**のであって、仕様が先に在るのではない。
- **全部を採ること** —— 要らない。⚠ **handoff は aim に依存しない** ∴ baton だけ使うことができる。
  statusline も surface も、それぞれ独立に装着する。

## 想定している形

⚠ **1 人の人間が 1 つのセッションと対話しながら進める形が前提である。** これは規模の遠慮ではなく、
**機構が成り立つ条件**である —— 「目的は人間のもの」「迷ったら人間に escalate する」が 1 文で書けるのは、
**その人間が誰かを問う必要がない**からだ。🔴 **複数人で使うなら、誰が `aim:` を pin し誰が `state:` を
宣言するのかを、その project が自分で決めて書く必要がある。** ⚠ **道具はそれを代わりに決めない。**

## 実物を見る

この repository 自身が aim で駆動されている。**[`docs/aims/`](aims/) がその corpus であり、
ここに書いた契約が実際に効いている姿である** —— 目的の 1 文、エージェントが書いた手段、
人間の宣言待ちで止まっている node。⚠ **作り物の例ではない。**
