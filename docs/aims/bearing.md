# IS

**この repo が想定するのは個人開発である。** 1 人の人間が 1 つのセッションと対話しながら進める形 —— いわゆる vibe coding —— が前提であり、⚠ **それは規模の遠慮ではなく、機構が成り立つ条件である。** 「目的は人間のもの」「迷ったら人間に escalate する」「達成の宣言は人間が行う」は、**その人間が誰かを問う必要がない**からこそ 1 文で書ける。⚠ **複数の人間が関わる project では、この体制は『誰に escalate するのか』を別途決めない限り成立しない** —— それは道具の設定ではなく、その project が自分で書くべき前提である。

**器は与えられている。** 本 repo は場を作らない —— agent が動く場所は標準ハーネスが既に十分に供給しており、それを wrap する仕事はもう空いていない。∴ 手段は「**外付けの拡張**」に限られ、現時点でそれは Claude Code の plugin である。⚠ **plugin は手段であって目的ではない。** `aim:` が「拡張機構」でなく「外付けの拡張として供給する」と述べているのは、器が変われば形も変わるからだ。

**供給の形は 3 つあり、選択は「宣言をどこに置くか」に尽きる。** 本 repo が採っているのは project の `.claude/settings.json` に `extraKnownMarketplaces` ＋ `enabledPlugins` を書く形で、⚠ **tracked ゆえ clone した者にも同じものが載り、載っている事実自体が git に残る。** 他に `~/.claude/settings.json` へ書く形と、user scope で `claude plugin install` を打つ形があり、この 2 つは cwd に依らず**全 project**に効く。⚠ **だがどちらも untracked である ∴ 載せたという記録がどこにも残らない** —— 前身が `~/.claude/skills/aim` の symlink で全 dir に載り、やがて所在が分からなくなったのと**同じ層の同じ罠**であり、`bearing-trace` にも原理的に映らない。∴ **「全 project に効く」と「載っていることが後から辿れる」は、この層では両立しない。** ⚠ どちらを取るかは、機構の性能ではなく人間が何を失う覚悟をするかの問いである。 ⚠ **2026-09-02、この二律は仮定でなくなった** —— 同日 user scope の install が実際に起き、**tracked な宣言と untracked な entry が同時に効いている**。踏んだ記録は `~/.claude/plugins/installed_plugins.json` にしか無く、**本 repo からは辿れない。**

**⚠ 同日、人間が project スコープを選び、user スコープを外した。** 理由は 2 つある —— ⑴ **user スコープは「より汎用的で普遍なもの」の置き場**であり、bearing は `docs/aims/` という **doc 構成を前提にする** ∴ そこへ置く性質のものではない。⑵ **他人の repo へ貢献するとき、明らかに邪魔になる。** ⚠ **そして記憶で答えられなくなる事態は、選択より先に既に起きていた** —— 人間は user スコープに入れた覚えが無く、実際には入っていた。上が述べた untracked の罠は、**予測ではなく観測になった。**

⚠ **だが「邪魔さ」を実測すると 1 箇所に集中していた。** PreCompact は corpus と `.handoff/` の不在を見て既に自ら降りており、UserPromptSubmit も PostToolBatch も黙る。⚠ **残っていたのは SessionStart だけで、しかも害は量ではなく偽だった** —— frame の冒頭が無条件に断定していた。∴ **スコープの選択とは別に、frame 自身の欠陥として直した**（[[aim-tree]]）: **宣言していない repo へ届かないこと**と、**届いた先で嘘をつかないこと**は別々の穴であり、片方を塞いでももう片方は残る。

**⚠ 供給したものが届くかは `version` 宣言が握っており、道具の側もそれを前提にしている。** `plugin.json` が `version` を宣言している以上、**上げない限り既存の利用者は古い cache を持ち続ける** ∴ bump は release の一部である（受ける側の門と併せて `README.md` の配布節が述べる）。⚠ **`claude plugin tag` は `{name}--v{version}` の git tag を作る際に、`plugin.json` と marketplace entry の version が一致していることを検証する** —— 「忘れれば黙って届かない」を機械で止める手が、既に道具の側に在るということである。⚠ **ただし現 `marketplace.json` の entry は `version` を宣言していない ∴ この検証が実際に何を見るかは未実測**であり、使えると書いてあるのではなく、**まだ試していない**と書いてある。

⚠ **2026-09-02、project スコープだけで供給した帰結が、受け取り側にも出た。** 宣言が project の `.claude/settings.json` にしか無い ∴ `installed_plugins.json` に bearing の record は 1 つも無く、**`/plugin update bearing` は仕事をしても一言も出さない** —— 実際に cache へ `0.7.0` が入ったのだが、それを確かめる手段は file の時刻だけだった。⚠ **成功と失敗が画面上で同じ見た目になる** ∴ 届いたかは cache の dir を見るしかない。⚠ **「ならば marketplace update だけで届く ＝ 開発中に打つコマンドが 1 つ減った」という読みは、時刻が否定した** —— あちらは先に `installed_plugins.json` を書いて仕事を終えており、`0.7.0` が生まれたのはその 31 秒後の `/plugin update` である。**減ってはいない。** ⚠ これは [[ambient-display]] が自分の面に課した「不在を黙って消さない」の、**道具の側での破れ**である —— 我々には直せない層に在る。⚠ **そして「受け取れた」という報告が無いことは、下段の 2 つの複製のうちどちらが走っているかが repo から見えないのと、同じ穴の別の現れである** —— あちらは走っている最中に見えず、こちらは受け取る瞬間に見えない。

⚠ **2026-09-03、その沈黙の正体が分かった —— 黙っていたのは update ではなく機構そのものである。** tracked な宣言（`extraKnownMarketplaces` ＋ `enabledPlugins`）は **enable はするが install はしない** ∴ `installed_plugins.json` に record が無い間、bearing は**どのセッションにも載っていなかった** —— skill 3 枚も hook 4 枚も、1 つとして走らない。⚠ **前段が「仕事はしているのに報告だけが無い」と読んだのは誤りで、載ることに関しては仕事もしていなかった**（cache へ `0.7.0` が入ったのは *update の*仕事であって、載ることとは別の事象である）。⚠ **∴ user スコープの record を外した瞬間から、bearing は自分の repo の中ですら動いていなかった** —— そして木には「動いてはいる」と書かれた。**悪いセンサーは無いセンサーに劣る**が、機構ではなく*木*の側で起きた形である。

**復旧は `claude plugin install bearing@trust-delta --scope project` の 1 手**で、`installed_plugins.json` へ `projectPath` つきの record が入る（tracked な `.claude/settings.json` は 1 文字も動かない）。⚠ **record が入ると `/plugin update` は喋り出す**（`bearing is already at the latest version (0.7.0)`）∴ **あの沈黙は道具の破れではなく、record の不在の症状だった** —— 前段の「我々には直せない層に在る」は取り下げる。

⚠ **∴ 上段の二律は、より鋭い形へ言い直される。** 「tracked ゆえ載っている事実自体が git に残る」は**半分しか真でない** —— git に残るのは**載せる意志**であり、**載っている事実は untracked な `installed_plugins.json` にしか無い**。∴ **project スコープを選んでも untracked の罠は消えず、効く範囲が狭まるだけである。** ⚠ **意志と事実は黙って食い違いうる** —— 実際に丸 1 日食い違った。

⚠ **供給された機構は、この repo の中では 2 つ在る。** hook の宣言は `${CLAUDE_PLUGIN_ROOT}` に釘付けで cache を走らせ、statusline は project の path に釘付けで working tree を走らせる ∴ **同じ機構の 2 つの複製が同時に走り、片方だけが新しい**。⚠ **2026-09-02 に実際に食い違った** —— statusline は照合記録を読んで flag を落としたのに、hook は cache 0.5.0 を走らせて同じ flag を出し続けた。**この repo は自分自身の古い版を食べていた** ∴ ドッグフーディングは bump の間隔だけ遅れる。

⚠ **これを「揃える」と、開発の即時性と配布の一貫性のどちらかを失う。** ∴ 揃えるのではなく**選ばせた**: cache の複製は、自分が bearing の checkout の中に居ると分かったとき working tree 側へ委譲する。開発中は working tree、他 project では cache が*自動で*選ばれる。⚠ **判定は repo の code に載る** —— cache を working tree へ symlink する案と違い、machine-local な不可視の細工にならない。⚠ **ただし shim は cache 側に住む ∴ 版の門は消えず、「毎リリース効く門」から「shim を変えたときだけ効く門」へ縮むだけである。**

**3 点である根拠は、今のところ「実際に足りなかった」以上のものではない。** 人間のワークフローで標準ハーネスだけでは満たされなかったものが、目的の保持・文脈の引き継ぎ・ズレの検知の 3 つだった。⚠ **これは基準から導いた選別ではなく、観測された欠落である** ∴ 4 つ目が現れれば `aim:` は動きうる。抽象的な基準を先に立てて 3 つを演繹しなかったのは意図的で、**制約は検証から後ろ向きに accrete する**という規則に従っている。

**⚠ [[native-language]] は、その「4 つ目」ではない。** あれが述べるのは*この repo がどう書かれるか*の制約であって、標準ハーネスに**観測された欠落**ではない —— 母語に揃えるかどうかは器の性質ではなく、この project が自分自身に課す規律である。∴ 上の条項を発火させず、`aim:` は動かない。⚠ **この判別はエージェントの call であり、人間が覆せる。**

**⚠ 2026-09-02、人間が「3 点は 3 点である」と述べた。** [[ambient-display]] と [[surface-parity]] が扱う statusline は、**公式 CLI という標準ハーネスが既に備える機能**であり、そこへ ctx / aim / drift を載せているのは*我々が付与する追加の情報表示*にすぎない ∴ **4 つ目の欠落ではなく、3 点をスムーズに遂行させる手段である。** `aim:` は動かない。

⚠ **この判定は「属するか属さないか」の二分からは出なかった。** エージェントは、1 行目が運ぶ context / plan usage が上の 3 語のどれにも収まらないことまでは言えた —— だが*遂行を助ける*という**第三の関係**を立てられるのは、目的を持つ側だけである。⚠ **この差は「4 つ目が現れれば `aim:` は動きうる」の運用そのものに効く**: 新しい関心が現れるたび、それが柱なのか柱を支えるものなのかを問い直すのは人間の act であり、機械が数えられるのは*どれにも一致しない*ところまでである。

**⚠ この corpus は 2026-09-01 に新規に播かれた。履歴を読む fence は当面 構造的に沈黙する。** `drift-intra` は anchor の*変更* commit を trigger にし、`drift-inter` は「一緒に commit されていない隣接」を見、`checkpoint-stale` は `last-verified` の経過を数える。誕生 commit しか無い corpus では 3 枚とも空になる。⚠ **空を「健全」と読んではならない。** これは道具が壊れているのでも corpus が綺麗なのでもなく、**噛むものがまだ無い**という第 3 の状態であり、区別できるのは本節がそう書いてあるからだけである。

**履歴を運ばなかったのは、公開の重みより先に、前提が違うからである。** 3 機構は前身プロジェクト `tmai`（*tactful multi agents interface*）の中で育ったが、あちらの履歴は一貫して「**tmai という場所の中での役割・手段**」を前提に書かれている。本 repo が問うのは「**外付け拡張としてどうか**」であり、出発点が違う。⚠ **履歴を運べば、あちらの判断を正しかろうと誤っていようと丸ごと継承する** —— これは前身が 2026-08-31 に「正本は実装ではなく `aim:` 文である」と判断したときに退けたのと、同じ構造の誤りである。∴ **概念は継承し、履歴は継承しない。** 3 柱はここから別の道を歩みうる。
