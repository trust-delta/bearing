# IS

**壊れているのは可視性ではなく、所有と可視性の逆立ちである。** 木は `parent:` の中にしか無く、`docs/aims/` は平らに並ぶ。⚠ **エージェントは全 file を読めば木を再構成でき、実際に毎セッションそうしている** —— できないのは、**その木を所有している人間のほうである。** [[aim-tree]] は「人間**だけが**動かせる不動点」と述べるが、⚠ **見えないものは動かせない** ∴ あの宣言は今のところ名目に留まる。本 node が埋めるのはその落差であって、新しい能力ではない。

**面は 2 つを同時に行う。** 木を構造のまま描くことと、**人間の欄だけを編集可能にすること**（`aim` / `parent` / `state`）。⚠ **後者は利便ではない。** canon は「frontmatter は人間のもの、body はあなたのもの」と定めているが、⚠ **今この境界を守っているのは、エージェントが指示に従っているという事実だけである** —— file の上では `state:` の 1 行と body は同じ md に同居し、区別は**書かれた法にしか存在しない**。面は同じ線を反対側から挟む: **人間には frontmatter しか触れない面、エージェントには法だけがある file。**

⚠ **費用は実演されている**（2026-09-03）。人間が「[[native-language]] は観測完了」と述べたとき、着地までに 3 手を要した —— エージェントが手を止め、`done` か `open` かを問い、選択を転記した。⚠ **うち 2 手はエージェントの介在であり、そこは宣言を取り違えうる経路でもある。** `aim:` の「エージェントを介さずに」は、この 3 手を 1 つの act へ畳むことを指している。

**手段は、静的な HTML 1 枚と File System Access API である。** ⚠ **build も依存も server も常駐 process も要らない** —— [[bearing]] は「build 手順も無い」を理由に npm を第 2 の配布経路から外し、YAML library も拒んでいる ∴ **React も vite も同じ理由で採れない。** ⚠ **そして corpus は browser 自身が読む ∴ 面は生成物ですらなく、置いてある 1 枚でよい** —— どの repo の `docs/aims/` を指しても動く。

**⚠ 実現可能性は推定ではなく実測である**（2026-09-03、Chrome 140、`file://`、headed、専用プロファイル）:

| 測ったこと | 結果 |
| :-- | :-- |
| `isSecureContext` ・ FSA API の在否 | true ・ 在る |
| `mode:'readwrite'` での pick | **ダイアログ 1 回で `granted`**（2 段にならない） |
| 列挙・読み取り | 8 node。**frontmatter が日本語ごと正しく読めた** |
| **書き込み** | 書いて読み直して一致 |
| **IndexedDB（`file://`）** | **生きている** ∴ handle を持ち越せる |
| 同一セッション内の reload | **`granted` のまま。クリック 0 回で書けた** |
| **ブラウザ再起動をまたぐ** | handle は**生存**、許可は **`prompt` へ落ちる** |
| 落ちた許可の回復 | **1 クリックで `granted`。ディレクトリの選び直しは不要** |

∴ **日常の費用は「起動後の最初の 1 クリック」だけである。**

⚠ **推定は 2 度外れた** —— 「`file://` では FSA が使えない」も「静的 HTML では編集が閉じない」も、測れば偽だった。**どちらも docs の記憶から述べたものである。**

⚠ **前身は同じ問題を別の答えで解いていた。** tmai の "offline" mode は `file://` ではなく **vite dev server（port 1421）**の上に在り、"backendless" とは *engine（HTTP backend）を外した*という意味だった —— **serverless ではない。** ⚠ **∴ あちらの形は、我々が測った道が塞がっていたことの証拠ではない。**

**前身から引き継ぐのは 3 つの設計判断であって、code ではない。**

1. **書き戻しは `aim` / `parent` / `state` だけを書き換え、他の frontmatter 行と body を byte 単位で保存する**（`parent` が消えれば行ごと落として re-root、新設なら `aim:` の直後へ）。⚠ **canon の境界が、そのまま code になっている形である。**
2. ⚠ **YAML library を使わない** —— 単一行 scalar の往復を手で書く。**前身も独立に同じ答えへ着いていた**（corpus の frontmatter 値は常に 1 行ゆえ、完全な emitter は要らない）。
3. slug の律（lowercase kebab・`--` 無し・先頭末尾 `-` 無し・**日付形でない**）は canon と一致する。

⚠ **引き継がないものが 1 つある。** あちらの format module は Rust engine の write surface の "faithful TS mirror" であり、**同じ契約が 2 言語に住んでいる。** 本 repo に engine は無く node 1 つ ∴ **この drift 源は最初から存在しない** —— ここは真似る対象ではない。

⚠ **その契約をどこに置くかは、測って 1 つに絞られた**（実測 2026-09-04、Google Chrome 140.0.7339.207、`file://`、既定フラグ、headless=new と headed の**両方**）—— `import('./x.mjs')`・`<script type="module" src>`・`fetch('./x.mjs')` の **3 つとも TypeError で塞がれた**。∴ 契約を別 file へ出すには生成が要り、⚠ **生成すれば「正本と生成物が一致しているか」を見る門が新たに要る** —— 腐りうる対が 1 つ増える。**HTML の中へ直に置けば、その門ごと不要になる** ∴ 契約は面の中に住み、**test はそこから取り出して走らせる**（複製しない）。⚠ **これは偶然にも、上段が「引き継がない」と名指した*同じ契約が 2 箇所に住む*形を、構造的に塞いでいる** —— 前身は同期を約束で守っていたが、ここには守るべき対が無い。⚠ **測ったのは既定フラグでの話である** —— `--allow-file-access-from-files` を渡せば変わりうるが、**面は人間がそのまま開くもの**であり、フラグを要求する道は採れない。⚠ **再測は安い**: 相対 import を 1 つ書いた HTML を `file://` で開けば済む。

⚠ **書き手が 2 人になる。** 人間が面で `state:` を回している最中に、エージェントが同じ node の body を書いている場面は現実に起きる。frontmatter しか書かないことは衝突を減らすが消しはしない ∴ **書き戻す前に読み直し、変わっていれば書かずに述べて止まる** —— `/bearing:statusline-setup` が既存の面を上書きせず止まるのと同じ律である。

⚠ **到達範囲は Chromium 系に限られる。これは我々の実測ではない。** FSA の対応状況から引き継いだ前提であり、前身も同じものを飲んで「Chrome / Edge で開いてください」と述べている。⚠ **測っていないことを、測ったことのように書かない。**
