# IS

**層が 3 つあり、機械が担うのは第 1 層だけである。** 安い機械検知＝**可視化**、エージェント＝検査と自明な保守、人間＝判断。⚠ **`aim:` が「判定はしない」と明記しているのはこのためで**、可視化が判定に滑ると、目的が満たされたかの宣言を機械が肩代わりすることになる。

**ズレは 2 種ある。** 同じ目的の中でのズレ（body が自らの `aim:` から離れる）と、目的どうしのズレ（隣接が互いを反映していない）。⚠ **trigger が違うので機構も分かれる** —— 前者は anchor の*変更*のみ、後者は*作成*も trigger になる（親を動かさず子を足す形があるため）。

⚠ **悪いセンサーは無いセンサーに劣る。** 数だけは権威に見えるので、黙って数え落とすことも、観測できないものを 0 に倒すことも、沈黙より悪い。**観測できなかったときは、そう言う。**

⚠ **可視化は無料ではない。** `aim:` の「安く」は機械側の計算量を指すが、**fence を読むのは人間とエージェントであり、そちらの注意にも予算がある。** 片付いた候補を出し続ける面は、**「問題なしと判断したものについて、問題の可能性があるので見よ」と言い続ける** —— これは可視化ではなく課税であり、⚠ **しかも課税された側はやがて fence 全体を読み飛ばす** ∴ センサーとしても壊れる。∴ **「検査したが変更不要だった」を書ける場所を持つことは、可視化が可視化であり続けるための条件である。**

⚠ **これは第 1 層が判定を始めたことではない。** 機械は依然として何も判定せず、**エージェントが書いた行を読むだけ**である —— 判定が層をまたいだのではなく、**エージェントの検査結果が、これまで書き留められる先を持たずに捨てられていた**のが埋まった。⚠ ∴ この行を機械が書いてはならない。書けば、そのとき初めて判定が層をまたぐ。

⚠ **沈黙は既に破れている。** `drift-inter` は 2026-09-01 に実地で発火し、2026-09-02 には [[ambient-display]] の誕生に対して噛んだ —— **本 node が「当面沈黙する」時期は終わった。**⚠ ただし沈黙が「ズレが無い」を意味しないという規律は、履歴が育っても変わらない: **噛まないことは、噛むものが無いことでも、ズレが無いことでもありうる。**

⚠ **可視化の出口が 1 つ増えた。** [[ambient-display]] は fence と同じ事実（未 commit / 未 push / drift）を statusline に常時描く —— **会話へ注入される fence と違い、token を食わず、人間が読み飛ばしても消えない**。⚠ **∴ 同じ法があちらにも及ぶ**: 採れなかったものを 0 と描かない、判定しない。実際あの面は不在を `?` で残している。

⚠ **2026-09-03、沈黙の範囲を取り違える形が、もう 1 軸で実地に出た —— platform である。** `boot-ritual` の CLI 名指し検査は `/node "\/.*\/bin\/handoff\.mjs" read/` と書かれており、**先頭 `/` を要求する ∴ POSIX でしか真になりえない**。win32 では常に落ちていたのに、**CI は ubuntu ゆえ緑であり続けた**。⚠ **「CI が緑」は「検査が通った」ではなく「*その platform で*通った」でしかない。** 上段が「ここが黙っていることは、あちらが黙っていることを意味しない」と言うのと同じ誤読が、センサーの*種類*ではなく*実行環境*の軸で起きた形である。

⚠ **そして常時赤い門は、門を持たないより悪い。** 落ち続ける 1 本は、読む側にやがて失敗そのものを読み飛ばさせる ∴ **センサーとしても壊れる** —— 上段の「課税された側はやがて fence 全体を読み飛ばす」と同じ機構が、候補の側ではなく*失敗*の側で起きる。⚠ **∴ 直し方は「その platform でも通るようにする」だけでは足りない**: 分岐を持つ機構は、**どちらの platform からも両方の分岐を検査できる形**にしておかねば、同じ穴がすぐ隣に空く（[[bearing]] の `lib/shell.mjs` が `platform` を引数に取るのはこの理由による）。

⚠ **この機構が見るのは、git 履歴の中の `docs/aims/` だけである。** ∴ **構造的にここへ映らない drift がある** —— README の日本語正本と英語版の食い違い、散文と code の言語の混在（[[native-language]]）。⚠ **2026-09-04、3 つ目が名指された —— 記録した実測が、外部の系が動いたことで偽になること**（[[observation-provenance]]）。⚠ **あれだけは別のセンサーで埋まらない** —— 上の 2 つは我々の側の 2 枚を突き合わせれば測れるが、**向こうが動いたかどうかは、こちらの file をいくら見ても分からない** ∴ あの node が採るのは「検知する」ではなく「**踏んだ人が自分で疑えるように書く**」である。それらには別のセンサーが要り、実際に `scripts/lang-report.mjs` が置かれて CI で毎回走る。⚠ **あちらも同じ法に従う**（可視化するだけで判定しない・落とさない）が、**ここが黙っていることは、あちらが黙っていることを意味しない。** 沈黙の範囲を取り違えないこと。

🔴 **2026-09-07、人間が「払い続ける」を選んだ**（人間の決定 2026-09-07）。⚠ **理由は、書いた瞬間の便益ではない** —— **`照合:` が効くのは、書き換えたその時ではなく、その判断が人間の記憶からもエージェントの context からも失われたときである。** 費用が防いでいるのは、近い未来のこの 3 つの形である（人間の言葉 2026-09-07）:

- 人間が**「不整合があるなら調べて整合を取ってください」と頼む羽目になる**こと
- エージェントが**「aim 同士で不整合がある。どちらが正しいか判断が要る」と差し戻してくる**こと
- **「片方だけを見ていたので誤った。答えはもう片方に在った」**が実際に起きること

🔴 **∴ 3 つとも、支払いを先送りした結果として*人間*が払う形をしている** —— `照合:` の 1 行は前払いである。⚠ **ただし「基本的に安く維持できるなら」という条件つきである** —— **ここでの「安い」は token 消費もだが、なにより人間が手間を掛けずに済むかである**（人間の決定 2026-09-07）∴ **この条件は失効しうる**: 人間の手が要る形に変質すれば、判断は戻ってくる。⚠ **現時点で `照合:` を書くのはエージェントである**（正本が「body はあなたのもの」と定めている —— **doc の読みであって実測ではない**）∴ **人間が払っているのは review の手間だけである。**

# PROCESS

- [done] plugin の drift 機構（intra / inter の 2 fence）を移設した
- [done] **`drift-inter` に「検査したが変更不要だった」を書く場所を与えた。** `# DAG` の `照合: [[slug]] @ <anchor_commit>` を機械が読み、その対を候補から落とす。⚠ **証言は commit に pin される** ∴ anchor が再び動けば対は候補へ戻る。⚠ **読めない sha（日付・在りもしない commit・曖昧な短縮）は候補を消さず、fence が読めない記録として名指す** —— 壊れた証言は無い証言より声が大きい、という `checkpoint.mjs` と同じ形である
- [done] **win32 で常時赤かった門 3 本を、どちらの platform からも両方の分岐を検査できる形にした。** ⚠ **2026-09-04、別マシン（repo が `D:`・home が `C:` の win32）で実測**: `node --test` は 291 pass / **3 fail** であり、内訳は ⑴ `bin/` の exec bit を working tree の mode で見る検査（⚠ **win32 は exec bit を持たない** —— node は `bin/` の全 file に `0o100666` を返す ∴ **原理的に通りえない門だった**）、⑵⑶ `unitSlug` の検査が POSIX 形の path を前提していたもの（win32 では `path.resolve` が drive letter を付ける）。⚠ **CI は ubuntu ゆえ 3 本とも緑であり続けていた** —— 上段の「CI が緑」は「*その platform で*通った」でしかない、の 2 度目の実地である。∴ **直し方は上段の法に従った**: `unitSlug` は `resolve` を引数に取り（`path.posix.resolve` / `path.win32.resolve` の両形を、どちらの platform からも検査する）、exec bit は **git の index が持つ mode** を第一の源にした —— ⚠ **配布されるのは index の側である**（消費者の cache は clone であり、POSIX の exec bit は `100755` から生える）∴ **両 platform で同じ答えを持つ唯一の場所**であり、判定は純関数 `isExecMode` へ出して 2 つの源を両方から踏めるようにした。⚠ **どちらの源からも読めないとき（win32 かつ index が無い ＝ cache から走ったとき）は skip し、理由を述べる** —— **「検査した」と「検査できなかった」を同じ緑に畳まない**
- [done] **fence が「ズレ無し」と「噛む履歴が無い」を別の文言で出すようにした。** `gatherDrift` が**絞り込みの働いた母数**を `scanned` として返し、`renderIntraFence` / `renderInterFence` がそれを 3 通りに描き分ける —— 母数 0 なら「まだ生じえない」、1 以上なら従来どおり「照合済み」、⚠ **`scanned` を渡さない呼び出しはどちらとも述べない**（知らないことを「ズレ無し」へ畳むのは、`bodyMoved` の `null` を `false` へ畳むのと同じ嘘である）。🔴 **穴は仮定ではなくこの corpus で鳴っていた**（実測 2026-09-06、対象: 本 repo の `docs/aims/`）—— **`scanned.intra` は 0**、すなわち **`aim:` 行は誕生以降まだ一度も変更されておらず**、intra fence は照合するものが無いまま「放置された record は無い」と述べていた（`inter` は `scanned: 10` ∴ あちらは本当に絞り込んで残らなかった）。⚠ **再測は `gatherDrift(repoRoot)` の `scanned` を見るだけである。** ⚠ **[[ambient-display]] の statusline は直していない** —— あの面は 0 を無表示にする設計であり、「噛む履歴が無い」を描けば**若い corpus すべてに常駐する segment**になる。**あちらが明文で拒んだ「元から無いものを、消えたものと同じ声で述べる」形に当たる** ∴ **面の設計の問いであって、この node が機械的に越境してよい先ではない**
