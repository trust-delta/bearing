# IS

**この目的は 2 つの半分から成り、後の半分が前の半分を裁く。**「どちらでも行える」が要求であり、「優先は WSL」は**両立が高くついたときに何を捨てるかを決める規則**である。∴ 本 node が持つ手段は「両方で同じように動かす」ことではなく —— ⑴ **platform に依る差を、名指した 1 箇所へ集める** ⑵ **集めきれない差は、黙らせずに述べる** ⑶ **捨てるときは Windows 側を捨て、捨てたと書く**、である。

⚠ **この目的が難しいのは code ではない。失敗が非対称で、しかも沈黙だからである。** CI は ubuntu 1 本しか走っていない ∴ **win32 でだけ壊れるものは機械に 1 度も映らない。** 実測 2026-09-10（この機体: win32、repo が `D:`・home が `C:`、node v24.18.1）—— `node --test` は ✖10、`scripts/consumer-check.mjs` は NG 4 で、**同じ commit の CI は緑だった**（`gh run list`、main 最新 ci は success）。

🔴 **そしてこれは新しい形ではない。木は既に同じ形を 2 度記録している** ∴ **3 度目である**（[[purpose-drift]]、2026-09-03 と 09-04）—— あちらの言葉では「**CI が緑**」は「*その platform で*通った」でしかない。

## 🔴 法は既に在った。2 つ目の実装が、それを通らなかった

⚠ **2026-09-04 の時点で、[[purpose-drift]] は答えを法として置いていた** —— 「**配布されるのは git が記録した mode である** ∴ **index は両 platform で同じ答えを持つ唯一の場所**」。純関数 `isExecMode` にしてあり、その doc は理由まで書いている:

> ⚠ **純関数にしてあるのは、どちらの platform からも両方の分岐を検査できるようにするためである** —— **片方でしか踏めない分岐は、直したそばから同じ穴を隣に空ける。**

🔴 **その隣の穴が、実際に空いていた。** `scripts/consumer-check.mjs` は同じ判定を **working tree の `stat()` で**行っており、win32 で偽陽性を出し続けていた（実測 2026-09-10 —— `bearing-ci.mjs` は index で `100755` なのに NG）。⚠ **法が無かったのではない。法が在り、2 つ目の実装がそれを通らなかった。**

⚠ **∴ 本 node が読む手段の中心はここに在る**: platform の差は「気をつける」で閉じない —— **判定が 1 箇所に無ければ、法は 2 つ目の呼び出し元で黙って破れる。**

## 優先が WSL であることの、今の意味

⚠ **2026-09-10 の時点では、この repo の開発は Windows 側で行われていた**（実測 2026-09-10: `process.platform === 'win32'`、cwd は `D:\trust_project\bearing`、home は `C:\Users\umu_s`）—— **pin された優先順位と、実際に開発が起きている場所は一致していなかった。**

✅ **2026-09-14、一致した。** 人間が **Windows 機に WSL を導入し、開発環境を WSL へ統一したと宣言した**（人間の決定 2026-09-14）—— ⚠ **これは `# ESCALATION` が待っていた act そのものである** ∴ 旧い項目はここへ事実として畳んだ。実測（2026-09-14、対象: この session が走っている場）: `process.platform === 'linux'`、`uname -r` は `6.18.33.2-microsoft-standard-WSL2`、cwd は `/home/umu_saito/works/bearing`、home は `/home/umu_saito`、node v24.21.0。⚠ **checkout も home も WSL の側に在り、`D:` と `C:` を跨ぐ形は解消している。** ⚠ **再測は上の 1 行**（`node -e` で 4 つを印字する）。

⚠ **旧環境に残っているものを、消える前に検めた**（実測 2026-09-14、対象: `D:\trust_project\bearing` と `C:\Users\umu_s\.bearing`。**いずれも読み取りのみ** —— `--no-optional-locks` で index も書いていない）。⑴ **checkout は branch `carrier-boundary`（tip `d32fad2`）の上に在り、この branch は remote から既に消えている**（`git ls-remote --heads origin` は `main` 1 本だけ）∴ **あの 5 commit は、あの disk にしか無い。** ⚠ **だが主張は `main` に在る** —— `d32fad2` 時点の `dev-platform.md` を今の `main` のそれと突き合わせたところ、**差は `main` 側が持つ改良（sha → digest の振り替えとその説明）だけ**だった ∴ **失われるのは squash 前の粒度であって、記録ではない。** stash は 0 件。⑵ **baton 5 本が旧 home に在り、`active.md` は `read-at` 済み** ∴ **未読の引き継ぎは 1 本も無い。** 🔴 **どちらも、消すか残すかは人間の act である** —— 本 node は検めて述べるまでである。

# OBSERVATION

⚠ **2026-09-14、票を 2 つ外した** —— **「WSL で 3 門が緑になるか」と「LF 固定が他の機体で何を起こすか」は、どちらも測れるようになり、測った** ∴ 結果は `# IS` と `# PROCESS` に在る。**この節に残るのは、私には確認できないものだけである。**

- **WSL 以外の場で、win32 でしか起きない摩擦に誰かが当たるか。** ⚠ **統一で「行き来して開発する」形が消えた** ∴ **旧い票（行き来したときの摩擦）はもう投じられない** —— 投じうるのは **他者の機体・CI の win32 leg・消費者**の側だけである。⚠ **これは門では出ない** —— 門が見るのは我々の code の振る舞いであり、**path の打ちにくさ・editor の挙動・起動の速さは、使った人間にしか見えない。**
