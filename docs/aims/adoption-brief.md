# IS

**この面が述べるのは*契約*であって、corpus の要約ではない。** 🔴 **要約は複製であり、複製した側が先に古くなる** —— この repo が一貫して拒んできた形である（`CLAUDE.md` の記録の作法、[[aim-tree]] の canon 1 正本、handoff の `read.md` / `write.md` が別名 command に手順を持たせない理由）。⚠ **∴ corpus を畳んで「入門」を作る道は採らない。**

**代わりに述べるのは、corpus のどこにも 1 箇所には書かれていないものである** —— 🔴 **採ると何が repo に置かれ、その後どの act が人間に残り続けるか。** ⚠ **今それは散っている**: [[adoption-declaration]] は*機構*として痕跡の残る側にだけ宣言を要求し、[[aim-tree]] は所有の非対称を規定し、[[human-domain]] はそれを人間が動かす面を述べる —— **どれも「採ろうとしている人が、採る前に読むもの」としては書かれていない。** ∴ **これは要約ではなく、新しく述べるべきものである。**

⚠ **欠落は 2 つ、実際に測った**（実測 2026-09-09、対象: `README.md`(173 行) / `README.en.md` / `CONTRIBUTING.md`。**再測は `grep` 2 本**）:

⑴ **「aim とは何か」を人間へ説明したものが無い。** README が持つのは表の **1 行**だけで、node の節（`# IS` / `# PROCESS` / `# OBSERVATION` / `[todo]`）は **1 度も現れない**（grep 0 件）。⚠ **実質の説明は `aim-authoring.md` だが、あれはエージェント宛の指示であり、しかも `/bearing:setup-aim` が消費者の repo へ*置く*ものである** ∴ **採用を決める前の人間が読む面としては、存在しない。**

⑵ **面に毎ターン出る 4 つの数の意味が、どこにも書かれていない** —— `todo` / `宣言待ち` / `escalation` / `観測票なし`（grep 0 件）。🔴 **あれは「人間の番がいくつ渡っているか」を述べる数である** ∴ **意味を知らない読み手の画面では、ただ数字が 4 つ並んでいるだけになる。**

**∴ 手段は 4 つで決まる。**

**⑴ 置き場は README ではなく、別の 1 枚にする。** ⚠ **README は既に導入・採用・装着・更新の*参照*として厚い** ∴ **そこへ契約を混ぜれば、毎回引かれる手順書の中に、1 度しか読まれないものが埋もれる。** README からは 1 行で導き、**README 自身は手順の面のままにする。**

**⑵ 版で腐る字を持たせない。** ⚠ **node 数・版番号・その日の count は動く** ∴ **literal で書けば書いた瞬間から古くなり、しかも黙って古くなる。** **述べるのは構造と act であって、その日の値ではない。**

**⑶ 実例は引き写さず、指す。** ⚠ **入門が例を持たなければ読者は木を想像するしかないが、node を本文へ複製すれば ⑴ の禁（複製した側が先に古くなる）を自分で破る** ∴ **この repo 自身の corpus を*指す*。**

**⑷ 英語版を併置する。** ⚠ **判別線は既に決まっており、本 node が決めるものではない** —— [[native-language]] の「**読む面**は英語を併置し、**開発に加わる面**は日本語のみ」。**この面は読む面である。**
