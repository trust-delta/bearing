# IS

**分割は所有で引く。** 目的（`aim:` 1 文）は人間のもので、エージェントは書き換えない。手段（body）はエージェントのもので、人間は妥当性を確認する。⚠ **この非対称が機構の全てである** —— 目的まで書けるエージェントは、達成できない目的を達成できる形に書き直せてしまい、そのとき失われたことは誰にも見えない。

**置き場はリポジトリである。** 目的は git artifact として commit され、vendor の memory にも会話にも住まない ∴ 機械が変わっても vendor が変わっても目的は残る。これは [[session-handoff]] が時間方向で担うことの、空間方向の対応物である。

**木で構造化する。** 1 目的 1 ファイル、親が目的、子が小目的。⚠ **body の中に階層を作り始めたら、それは子 aim が隠れている合図**であって、見出しを足す合図ではない。

⚠ **実装は前身から運ぶが、正当化は運ばない。** コードは動く実体として持ってくる。だがそれが *外付け拡張として* 妥当かは、ここで実際に使いながら書き直す。

**⚠ 置き場は repo だが、repo の中のどこかは project が決める（2026-09-03）。** 既定は `docs/aims/` のまま動かさない —— **既定が動けば、既に在る corpus が一斉に行方不明になる。** ⚠ **変えられるようにする理由は、[[bearing]] が全 project に載る形を採ったことである**: `docs/` が生成物である repo、package ごとに分ける monorepo、そもそも `docs/` を持たない repo に対して、**我々の doc 構成を採用の条件として押し付けない。**

⚠ **在り処の宣言は、採用の宣言と同じ 1 つの宣言である** —— [[bearing]] が `CLAUDE.md` へ置く marker が `dir=` を運ぶ。`dir=` が無ければ既定 ∴ **既に置かれた block は何もしなくてよい**（前方互換）。

⚠ **glob にはしない。3 つとも実測に基づく。** ⑴ **5 箇所が dir を git の pathspec として渡している** ∴ glob は pathspec magic の意味論に触れ、**走査が黙って広がりうる**。⑵ **slug が衝突する** —— `a/aims/x.md` と `b/aims/x.md` はどちらも slug `x` になり、`parent:` と `[[link]]` の解決が壊れる。**単一 root は木の同一性そのものに入っている。** ⑶ **「corpus が無い」と「別の場所を見ていた」が区別できなくなる** —— この repo が一貫して拒んできた沈黙の畳み方である。∴ **許すのは 1 つの明示的な dir だけ。**

⚠ **エージェントが「これを書いてよいか」と問うたなら、その問い自体が「書け」を意味する**（人間の決定 2026-09-08）。🔴 **`# IS` はエージェントの解釈を置く節である** ∴ **自力で導出できなかった解釈こそ、この節に欠けていたものである** —— **問うたという事実が、その不在の証拠である。**

⚠ **これは上段の非対称と矛盾しない。** 🔴 **問うべきは `aim:` を動かすときであって、`# IS` に解釈を足すときではない** —— **前者は人間の所有物に触る act、後者はエージェントの所有物を埋める act である。** ⚠ **2026-09-08、この repo のエージェントが後者で問うた** —— 導いた解釈を書いてよいかを尋ね、**人間は「聞いてくれたことそのものが、書くことを指示します」と述べた。**

⚠ **害は沈黙の側に在る。** 問いは往復を 1 つ増やすだけに見えるが、🔴 **問うて答えが来なければ、その解釈はどこにも残らない** —— **導出できなかったものは、次の世代も導出できない。** ⚠ **∴ 迷いは escalate の合図であると同時に、記録の合図でもある** —— **どちらを選ぶかは、触る先が誰の所有物かで決まる。**

⚠ **この規則は、この repo の corpus にだけ置く**（人間の決定 2026-09-08）—— **配る canon（aim skill の `aim-authoring.md`）へは昇格させない。** 🔴 **∴ 配る側で同じことを探しても無い** —— **無いのは漏れではなく決定である。**

⚠ **2026-09-10、frontmatter は 3 field になった**（人間の決定）—— 🔴 **「私が frontmatter に求めるのは『目的の一文・親を示す・満足と諦めの状態』のみ」** ∴ **`aim:` / `parent:` / `state:`。**

🔴 **4 番目の `last-verified:` は退役した**（同日）。⚠ **人間が sha を書く欄であり、host の merge 慣習がそれを書き換える** ∴ **人間の要求「aim は repo を問わず機能する」を満たせない。** **aim⊥code の剥離は [[purpose-drift]] の `bearing-aim-code-stale` が `[done]` mark の commit から引く** —— 🔴 **人間は 1 文字も書かない。** ⚠ **能力の後退は無い**: **`checkpoint-stale` は人間の刻印を持つ node にしか発火せず、数えていたのは repo 全体の commit であった** ∴ **置き換えが見えない場所は、あちらも見えなかった**（保有数は最後まで 0 だった。実測 2026-09-06 および 2026-09-10）。

⚠ **退役は削除ではない。** **既に `last-verified:` を書いた消費者の corpus は 1 文字も動かない** —— **「知らない frontmatter の行」を保つ振る舞いが、そのまま後方互換になっている**（`test/claude/bearing/aim-format.test.mjs` が固定）。

# ESCALATION

⑴ **`[todo]` の法が「外部依存の解消待ち」を todo として通す。判別線を書き換えるか。** 🔴 **2 repo で独立に出た**（人間の報告: 1 件目 2026-09-09、2 件目 2026-09-12 —— 逐語: 「**先日とあるrepoで、外部依存待ちがtodoとして記述されていたのを暫定でESCALATIONにおいたのですが、別のrepoでも同様の事象を確認。現在の法はエージェントには「外部依存の解消確認はtodo」と捉えられるようです**」）。⚠ **これはエージェントの不注意ではない —— 法の字面がそう述べている。**

✅ **字面を確かめた**（実測 2026-09-12、対象: `carriers/claude/bearing/templates/aim/frame.md:9`）—— 判別線は「**あなたが自力で完了を*確認*できることだけを書く**」であり、除外として列挙されているのは「**人間の観測・判断を完了条件に持つもの**」の 1 型だけである。🔴 **外部依存の解消待ちは確認できる**（検査を走らせれば解けたか分かる）**∴ 判別線を通り、列挙にも当たらない** —— **法に照らして todo で正しい。** ⚠ **以前の当方の読みは当たっていたが、法が住む file を取り違えていた** —— **`aim-authoring.md` ではなく `frame.md` であり、あれは配る block ＝ 消費者の `CLAUDE.md` に入る側である** ∴ **射程はこちらが思っていたより広い。**

🔴 **害は、法が自分で述べている理由がそのまま効く。** 「`open-todo`（＝ エージェントの残務）に人間待ちが混ざって数が嘘になる」—— ⚠ **外部待ちも残務ではない** ∴ **同じ形で、同じ理由で嘘をつく。** 🔴 **∴ 欠けているのは理由ではなく列挙である。**

⚠ **同型は 2026-09-06 に一度裁かれている**（`# PROCESS`）—— **人間の観測待ちは「`[todo]` にも `# ESCALATION` にも倒さない」と決まり、`# OBSERVATION` という新しい箱を得た。** **そのとき articulate された尺がここでも効く**: 🔴 **escalation は「進めない」、宣言待ちは「終われない」。** **外部待ちは「進めない」側である** ∴ **escalation が*近い*** —— ⚠ **だが escalation の定義は「進めない」だけでなく「*人間の判断*が要る」まで含む。**

🔴 **∴ 位置は「判断が在るか」で割れる。当方の推奨は、新しい箱を作らず 3 つに振り分けることである**（⚠ **確定は人間の act** —— **`frame.md` は配る法であり、2026-09-06 に人間が射程を自分の側へ引き上げた領域である**）:

- 🔴 **検出できるなら、todo を「解けたことを検出できるようにする」へ書き換える。** ✅ **法が既に持っている idiom である**（「人間の観測が要ると分かったら、todo を『観測できるようにする』へ書き換える」）—— **同じ move を外部待ちへ当てるだけで、新しい箱も新しい数も要らない。** ⚠ **しかも生まれるのは本物の残務である**（検出器を書く作業）∴ **`open-todo` が嘘にならない。**
- 🔴 **「待つか迂回するか」の判断が要るなら escalate する。** ⚠ **人間の暫定措置はこちらであり、思ったより筋が通っている** —— **ただし escalation に書くのは*依存の名前*ではなく*判断*である**（「待つ／回避策を採る」）。**依存を parking するだけなら、escalation の数が「判断待ちの数」でなくなる。**
- 🔴 **判断も検出も要らない（ただ時を待つ）なら `# IS` の残留リスクである。** ✅ **canon が既にそう述べている**（`aim-authoring.md`: 「残留リスク → IS へ」）—— ⚠ **どの数にも出ないが、それが正しい。誰の番でもない。**

⚠ **`[wait]` mark と `waiting: N` を新設する案は採らないことを勧める** —— 🔴 **3 つ目の数は「どれが重いか」の割り当てを面に持ち込む**（この node が明文で禁じている形）。⚠ **そして `[wait]` は無期限の駐車場になる** —— **誰も片付けず、数だけが増える。**

🔴 **判別線そのものの書き換え候補**: 「自力で完了を**確認**できること」→「**自力で今*着手して終えられる*こと**」。⚠ **試すのは確認可能性ではなく着手可能性である** —— **外部待ちは確認できるが着手できない。** ⚠ **人間の観測待ちも同じ 1 本で落ちる** ∴ **列挙を増やすのではなく、判別線を 1 段強くする形である。**

⚠ **本 repo に生きた実例は 0 件である**（実測 2026-09-12、対象: `docs/aims/*.md` の `[todo]` 5 本 —— **すべて自力で着手できる作業**）∴ 🔴 **これは corpus の乱れではなく、配る法の欠落として上げている。**

🔴 **2026-09-13、人間が面から実地に見て「混ざっている」と述べた** —— 逐語: 「**エージェントの残務に人間待ちが混ざっていないかは機構そのものよりaim bodyの書き方によるかもしれません。混ざってはいますが、混ざっていると認識できるようになったことが意味を生みます**」（[[human-domain]] の 3 面のうち「エージェントの残務」を開いて）。

🔴 **これは直上の実測と食い違う。** ⚠ **どちらも書き換えない** —— **過去形の観測は偽にならない** ∴ **食い違いを述べる。** **材料を並べる**（実測 2026-09-13、対象: `docs/aims/*.md` —— `[todo]` **5 本 / 3 node**）:

- `aim-tree` —— 宣言待ちの caption が偽を述べている
- `dev-platform` —— exec bit の判定を 1 箇所へ寄せる ／ **CI が win32 でも同じ 3 門を走らせるようにする** ／ platform に依る分岐を機械が列挙できるようにする
- `observation-provenance` —— `provenance-report` が inline code span を散文として測っている

⚠ **どれが人間待ちかは、ここでは判定しない** —— 🔴 **それがこの escalation が求めている判断そのものである。** 🔴 **だが食い違いの形そのものが材料になる**: **当方は同じ 5 本を見て「すべて自力で着手できる」と読み、人間は「混ざっている」と読んだ** ∴ **判別線が、読む者によって別の答えを許している。** ⚠ **これは「どちらかが間違えた」ではなく、法が判別線として機能していないという観測である**（根拠は 2026-09-12 の当方の読みと 2026-09-13 の人間の読みの差そのものであって、どちらか一方の正しさではない）。 **再測**: `node -e` で `parseProcessMarks` を全 node に当て、`[todo]` 行を並べる。

🔴 **人間は害の側を 1 つ確定させた** —— **「認識できるようになったことが意味を生みます」。** ⚠ **これは混ざりが消えたという意味ではない** —— **`CLAUDE.md` の尺で言えば、気づけない漏れが気づける漏れに変わった** ∴ **安くなったが、無くなっていない。**
