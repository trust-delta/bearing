# aim の記録

🔴 **ここが aim の記録の正本である**（人間の決定 2026-10-29、`decisions/bearing-x02.json`）。作業機（WSL）の hub が作業窓へ仕事を渡す形では、記録が git に在り、作業窓のセッション開始時に hook が読めることが前提になる。

⚠ **2026-10-28 の試作では、正本を非公開の Artifact の DB に置き、ここはその写しとしていた。** 10-29 に向きを反転した ∴ **Artifact のページは、ここから作る人間向けの面である。**

**何が在るか** —— `docs/aims/` の node を、**人間が決めたこと**と**エージェントの解釈**に分けた記録である。**1 件 1 file** で、file 名が id である。

| dir | 1 file = |
| :-- | :-- |
| `nodes/` | 1 つの aim（目的・親・状態・主に属する機能） |
| `features/` | 1 つの機能。4 つの固定の枠（全体・作る・記録する・出力する）の下に置く。一覧は人間が確定した |
| `categories/` | 1 つの話題の分類（エージェントが付ける補助のタグ） |
| `decisions/` | 人間の決定 1 件。`form` が `verbatim` なら `quote` は人間の言葉そのもの、`paraphrase` ならエージェントの要約、`pinned` なら目的として固定された `aim:` の文 |
| `interpretations/` | エージェントの解釈 1 件。`basis` が依って立つ決定を名指す。⚠ **空なら、それはエージェント自身の選択である** |

⚠ **1 件 1 file にしたのは、並行する会話が衝突しないためである**（2026-10-29）—— hub の作業窓は会話ごとに worktree を切る ∴ 1 つの file の末尾へ追記すれば、merge のたびに衝突する。

🔴 **決定は追記だけの記録である。** 書き換えも削除もしない —— 誤りは、それを正す決定を足して示す。

**形の検査** —— `test/claude/bearing/aim-db.test.mjs` が、この dir の記録が読めて形が整っていること（参照先の実在、`form` と `quote` の対応など）を固定する。読み書きの正本は `carriers/claude/bearing/lib/aim-db.mjs`。

**人間が見るページ** —— `node scripts/aim-db-page.mjs <出力する file>`。記録をページへ埋め込んだ HTML を書く（人間の決定 2026-10-29、`decisions/bearing-x09.json`）。ページは何も読みに行かない写しであり、どの commit をいつ写したかを出す。形の崩れた記録が在れば、書かずに止まる。publish はエージェントが行う。⚠ **その URL はここに書かない** —— この repo は公開であり、ページは非公開である。

**DB からの取り込み** —— `node scripts/aim-db-import.mjs <読み出した dir>`。`ArtifactData` の `list` に `out_dir` を付けて読み出した dir（この dir と同じ形）から、**正本に無い記録だけを足す**。正本と中身が食い違う記録が 1 件でも在れば、何も書かずに止まる。

⚠ **2026-10-29 の時点で、`docs/aims/` の本文はまだ並存している** —— どちらをどう退かせるかは決まっていない。
